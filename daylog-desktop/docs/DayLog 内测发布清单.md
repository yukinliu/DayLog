# DayLog 内测发布清单

## 当前判断

DayLog 已具备小范围、受控内测的核心能力：记录、自我觉察、事实经历、明细编辑、项目、统计、日历、本地资料库与 DMG 打包均已贯通。当前不建议直接公开发布给不熟悉 macOS 安全提示的普通用户。

## 内测前必须完成

1. 配置 `public/data/daylog-content.json` 的 `remoteContentUrl`，验证旧客户端可以收到新版提示。
2. 确认飞书下载页已包含当前 Apple Silicon 安装包、版本号、发布日期和简短安装说明。
3. 用全新 macOS 用户环境完成一次安装测试：打开 DMG、拖入 Applications、首次启动、创建资料库、退出、再次打开。
4. 用独立测试资料库完成一次核心回归：
   - 连续保存自我觉察与事实经历，重启后数据都存在。
   - 修改日期、项目和投入，原日期与新日期 Markdown 都正确。
   - 删除想法和事件，最后一条记录删除后对应空 Markdown 被移除。
   - 合并、删除项目后，关联事实经历仍可读取。
   - 更换资料库后，旧资料库内容不发生变化。
5. 决定首轮测试的安装信任方案：
   - 推荐：Developer ID 签名并完成 Apple notarization。
   - 仅限熟人内测：明确提供 macOS 首次打开未签名应用的说明。
6. 备份测试：复制整个 DayLog 资料库到其他位置，确认可以通过“打开已有资料库”完整恢复。

## 可以在首轮反馈后完善

- Windows 安装包。
- 应用内自动下载和替换程序；当前飞书下载已足够。
- 快捷键、窗口位置恢复和更完整的键盘操作。
- 自动化 UI 测试与大数据量性能基准。
- CSS 结构性拆分。目前样式文件较大，但生产体积和响应速度正常；首轮内测前只继续做局部收敛，避免视觉回归。

## 每次构建前

```bash
npm run release:check
npm run release:macos
```

`release:check` 会检查四处版本号、远程内容地址、飞书链接、100 件充能小事和打包图标；随后执行前端生产构建与 Rust 资料库测试。

## 当前自动验证覆盖

- TypeScript 严格类型检查。
- Vite 生产构建。
- 资料库初始化、读取、原子文件写入和 Markdown 删除。
- 记录创建、修改、删除及重启读取。
- 旧设置迁移与备份。
- 拒绝写入或删除资料库以外路径。
